# Wait, what

The last message didn't land. Pitch it again, so the user can follow it on a first read.

1. **Context first**: Open with a sentence or two on where the work stands and why this point matters, then make the point.
2. **Simplified Technical English**: Write in ASD-STE100: short sentences, one fact or instruction per sentence, common words used with one meaning, and the active voice. The project's terms and technical names stay as they are, as STE allows.
3. **The project's words**: Use the terms from `GLOSSARY.md` or `GLOSSARY-MAP.md` when either exists. Define any other term the first time it appears.
4. **Show it**: When the point is a flow, a structure, a sequence or a comparison, and a picture would be easier to follow than the sentences, add one. Use a small Mermaid diagram in a fenced `mermaid` block, such as a flowchart or a sequence diagram, or a table for a comparison. Draw only what the last message said, with the few parts the point needs.
5. **Only the part that lost them**: When the user asks about one term, define it in a sentence or two, with no context first. When they name a part, re-pitch that part. Otherwise, re-pitch the whole message.
6. **The same content**: Say what you said before, without new claims or a new plan. When the confusion shows that the message was wrong, say so instead.
